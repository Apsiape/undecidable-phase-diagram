## Choices and deviations

The port makes no new mathematical fidelity choice. The 29 source `[choice]` annotations are in `evidence/CHOICES.json`; H-1 to H-4, P-1 to P-51, [gap] 1–13 and QB's rulings remain in `STATUS.md` and `BLUEPRINT.md` (unchanged, historical).

- **Challenge construction.** `Challenge.lean` imports only Mathlib (the eight imports of `Statements.lean` and the four Mathlib imports of `Hypotheses.lean`) and contains byte-for-byte copies of both files after their import blocks, between BEGIN/END markers (the generator re-extracts and compares them), then the three holes with the binders of `Main.lean`. It never imports the development and never uses `type_of%`. Four visible auxiliary commands: `run_cmd … setMainModule` before each copy (as in the forgetting relay); `set_option backward.isDefEq.respectTransparency false` before the `Statements` copy and `true` after it (the option the development uses for `Statements.lean`); `set_option bootstrap.genMatcherCode false` around the `Hypotheses` copy. In one file Lean reuses an identical matcher: `Ising.val` reused `instReprSpin.repr.match_1` (from `deriving Repr` for `Spin` in the Statements copy), while the separate module `Hypotheses.lean` makes its own `Ising.val.match_1`. The matcher cache is keyed by this option, so the copy starts from an empty cache, as a fresh module does; the copy lies in a `noncomputable section`, and only code generation for its matchers is skipped. Whatever these options do, the comparator compares every constant of the three statements with the development, so a discrepancy can only make it fail.
- **Kernel binaries.** The forgetting relay replayed with Windows binaries in a directory this relay may not read. Here both replays use the Linux binaries of the same pinned toolchain (`leanchecker` sha256 `12c38901…`, the forgetting relay's recorded Linux binary; `nanoda_bin` sha256 `cbf13950…`), with the forgetting relay's nanoda policy, under the 9.0 GB watchdog (below its 9.9 GB cap). Toolchain, bubblewrap and vendor tree were copied with `cp -a` (digests identical, `evidence/BINARY-DIGESTS.json`; no hard links).
- **Memory incident.** Before any build, a probe `leanchecker --help` (no help flag: with no module it replays every module on its search path) and a bare `leanchecker` call were started without the guard; the WSL OOM killer stopped both at about 15.6 GB. Nothing was built or modified by them; every later process ran guarded. Otherwise the peak was the 4.2 GB build tree.
- The Windows host heartbeat (`relay/host-memory-monitor.py`) was written for this relay; minimum host availability observed: 9,539,317,760 bytes. It and every other process were stopped at the end.
- `find -newermt` shows no file created or modified in `/opt/forgetting-arxiv-2026-11-10`, its runtime archive and receipt, `/opt/package-forgetting-arxiv.py` or `/home/lean` during this relay (`evidence/SOURCE-AUDIT.json`).
